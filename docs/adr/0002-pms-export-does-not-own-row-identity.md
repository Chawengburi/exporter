# pms-export ไม่ถือความเป็นเจ้าของ "ตัวตนของแถว"

2026-09-17 · pms-export มีหน้าที่ **ดึงให้ตรงกับที่ PMS แสดงแล้วส่งต่อ** เท่านั้น
ไม่ประมวลผล ไม่รวมแถว ไม่ตัดแถวซ้ำ · ฝั่ง uploader เป็นเจ้าของ data ingestion,
data processing และการสร้าง dataset (ทีมอื่นดูแล)

ข้อเท็จจริงที่บังคับรูปแบบนี้: **uploader เก็บเป็นไฟล์/เอกสาร ไม่ใช่แถว** (PocketBase +
worker ทำ embedding, ค้นด้วย `document_type` / `source_system` / `time_events`) —
**ไม่มี upsert ระดับแถวด้วยเลขที่จอง** · ขณะเดียวกันตัวกรองวันของทุกรายงานเป็นอดีตล้วน
แถวที่สร้างเดือน ม.ค. แล้วถูกแก้เดือน ก.ย. จะยังอยู่ก้อน ม.ค. เหมือนเดิม **รอบรายวันจึง
มองไม่เห็นการแก้ย้อนหลังตลอดไป**

**ทางออกที่เลือก:** ส่งไฟล์สองชนิด — **รอบรายวัน** (ของใหม่ที่ขอบหน้า) และ **baseline**
(ทั้งช่วงใหม่หมด ค่าตั้งต้นเดือนละครั้ง) โดยใบ baseline ใหม่**แทนที่ใบเก่าในระดับไฟล์**
ซึ่งเป็นแนวคิดที่ uploader รองรับอยู่แล้วโดยไม่ต้องขอให้ทีมอื่นแก้อะไร

**ทางที่ไม่เลือก:** ให้ uploader ทำ upsert ระดับแถว — เป็นการแก้ระบบที่เราไม่ได้ดูแล
และผูกสองระบบเข้าด้วยกันด้วยคีย์ของ PMS

**ยังไม่ปิด:** ความถี่ baseline หนึ่งเดือนเป็นค่าตั้งต้นที่ยัง**ไม่ได้วัด** — ต้องดึง ส.ค. 2026
ใหม่แล้วเทียบ `sha256` กับ manifest ของวันที่ 2026-09-08 เพื่อให้ได้อัตราการแก้ย้อนหลังจริง
