# รายงานปฏิบัติการรายวัน (`Report.dailyOnly`) ดึงได้แค่วันนี้เท่านั้น — ไม่มี back-fill/baseline

2026-09-22 · pilot batch เพิ่มรายงานใหม่ (`.scratch/pms-export-new-report-pilot/`) เจอว่าหน้าอย่าง
Arrivals/Departures/In-house guests/Housekeeping กรองด้วย**วันปฏิบัติการ** (วันเข้าพัก/วันออก/
วันที่ปัจจุบัน) เป็นวันเดียว ไม่ใช่ created-date range แบบ 3 รายงานเดิม (`reservations-search`
ฯลฯ) — คนละแกนกันทั้งหมด: created-date ledger สะสมไปข้างหน้าเรื่อย ๆ (แก้ย้อนหลังยังมองไม่เห็นตาม
ADR-0002 แต่ยังสะสมได้) ส่วนวันปฏิบัติการคือ snapshot ณ ขณะนั้น เปลี่ยนได้ตลอดจนถึงวันนั้นมาถึง แล้วไม่มี
ความหมายให้ "back-fill" ย้อนหลังในความหมายเดียวกับรายงานอื่นเลย (จะดึง "รายชื่อผู้เข้าพักของวันที่
ผ่านไปแล้ว" ทำไมในเมื่อวันนั้นจบไปแล้วจริง ๆ)

**ทางที่เลือก:** ทำเป็นโหมดใหม่ `Report.dailyOnly = true` — รองรับแค่ `--daily` (แปลว่า "วันนี้
วันเดียว" ไม่ใช่ overlap 3 วันแบบรายงานอื่น) ปฏิเสธ `--from`/`--to`/`--last-days`/`--baseline`/
`--overlap-days` ทั้งหมดดัง ๆ ผ่าน `resolveDailyOnlyRange()` (`core/order.ts`)

**ทางที่ไม่เลือก:** ให้รองรับ `--last-days N` แบบวนดึงทีละวัน (N request) เพื่อจำลอง back-fill —
เป็นการเดาว่ามีคนต้องการฟีเจอร์นี้จริงทั้งที่ยังไม่มีใครขอ และต้นทุน/ความเสี่ยง (N ครั้ง login+ค้น
ต่อการดึงครั้งเดียว) ไม่คุ้มจนกว่าจะมีคนต้องการจริง

**ผลที่ตามมา:** รายงานกลุ่มนี้ไม่มี "baseline" ให้จับการแก้ย้อนหลังแบบ ADR-0002 เลย เพราะวันที่ผ่าน
ไปแล้วไม่มีความหมายให้ดึงซ้ำ — ถือว่ายอมรับได้เพราะไม่ใช่ ledger ตั้งแต่ต้น

**สถานะ 2026-09-28 — `--report all` ข้ามแทนการล้ม:** เดิม `--report all` ที่ไม่ใช่รอบ `--daily`
(back-fill, `--from`/`--to`, `--last-days`, `--baseline`) ส่งรายงานกลุ่มนี้เข้าไปด้วยแล้วโดน
`resolveDailyOnlyRange` ปฏิเสธ นับเป็น "ล้ม" 4 ใบ exit ไม่เป็นศูนย์ทุกครั้งทั้งที่ไม่มีอะไรผิด —
ตอนนี้ `partitionForRunAll` (`core/order.ts`) ข้ามพร้อมเหตุผล (`skipped` ใน JSON, `⏭ ข้าม` บนจอ)
ไม่นับว่าล้ม · สั่งรายงานกลุ่มนี้ใบเดียวตรง ๆ โดยไม่ใส่ `--daily` ยังปฏิเสธดัง ๆ ตามเดิม
