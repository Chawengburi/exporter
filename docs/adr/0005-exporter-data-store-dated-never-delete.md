# ผลของ exporter เก็บใน `data/<site>/<ชนิดรอบ>/` แยกโฟลเดอร์ตามวัน และไม่ลบไฟล์ที่ export มาเลย

2026-10-07 · เดิมรอบรายวันของ HotelTime เขียนทับ `downloads/` ทุกครั้ง แล้วสคริปต์บน Windmill
`cp -r downloads/` ไปเก็บที่ `downloads-archive/<วันที่>/` ผลที่ได้คือแต่ละวันมีสำเนาซ้ำของไฟล์ที่ไม่ได้
เปลี่ยนเลย ได้แก่ CSV ปี 2024/2025 ที่ค้างจาก back-fill และ `foodstory/` รายเดือน ใน 15 วันโตเป็น 337MB
ทั้งที่ข้อมูลใหม่จริงมีแค่ ~150KB ต่อวัน นอกจากนั้น ถ้ามีรายงานล้มแม้ใบเดียว ขั้น `cp` จะไม่รัน
ผลทั้งวันจึงไม่ถูกเก็บ

**ทางที่เลือก:** แบ่งชั้นแรกตาม **Site** แล้วแบ่งตามชนิดของรอบ (`daily/` `baseline/` `backfill/` `monthly/`)
รอบรายวันเขียนลง `daily/<YYYY-MM>/<YYYY-MM-DD>/` ของวันนั้นตรง ๆ ชื่อไฟล์ขึ้นต้นด้วยวันที่ของข้อมูล
และของที่คนไม่ค่อยเปิดอยู่ใน `_raw/` กับ `_summary.txt` · **ไม่ลบไฟล์ที่ export มาเลยตลอดไป**
รวมทั้ง baseline ใบเก่า (ใบใหม่แค่กลายเป็นใบอ้างอิง ความหมายของ ADR-0002 ยังเหมือนเดิม) และ FoodStory
ที่ดึงเดือนเดิมซ้ำให้เก็บเป็นโฟลเดอร์รอบใหม่แทนการเขียนทับ · ตอนย้ายของเก่า เก็บไฟล์ที่เหมือนกันทุก byte
(เทียบ sha256) ไว้ชุดเดียว เพราะการตัดสำเนาซ้ำไม่ทำให้ข้อมูลหายแม้แต่ byte เดียว

**ทางที่ไม่เลือก:** ใช้ `downloads*/` สี่โฟลเดอร์เดิมต่อไป แค่ล้างไฟล์ค้างและเลิกก๊อปซ้ำ — แก้น้อยกว่า
แต่ต้นเหตุคือการเขียนทับที่เดิมแล้วต้องก๊อปเก็บยังอยู่ ปัญหาไฟล์ค้าง/การทับกันของรอบต่างชนิดจะกลับมาอีก

**ดึงซ้ำแล้วได้ชื่อไฟล์เดิม (เพิ่ม 2026-10-14 เจ้าของยืนยัน):** ไบต์ต่างกัน → ไฟล์เดิม**ย้าย**ไป `_superseded/<เวลาที่ย้าย>__<ชื่อเดิม>`
ในโฟลเดอร์เดียวกัน และ `_manifest.json` บันทึกไว้ใน `superseded[]` · ไบต์เหมือนกันทุก byte → เก็บชุดเดียว · ไม่มีข้อยกเว้นให้ผลใหม่ลบหรือทับ
ของเดิม (คอมเมนต์ในโค้ด CSV เดิมที่เขียนว่ามีข้อยกเว้นนี้ ไม่ตรงกับ ADR)

**ผลที่ตามมา:** Windmill (mount ใน `windmill/docker-compose.yml` และสคริปต์ `pms_export_daily`) และ
ปลายทางในอนาคต (uploader) ต้องอ่านจาก path ใหม่ · พื้นที่ดิสก์โตไปเรื่อย ๆ โดยตั้งใจ ซึ่งรับได้เพราะ
ไม่มีการก๊อปซ้ำแล้ว
