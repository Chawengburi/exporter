# exporter เก็บและส่งไฟล์ดิบอย่างเดียว ทุกรายงาน และ uploader เป็นเจ้าของการแปลงกับการกำกับดูแลข้อมูล

2026-10-13 · เดิม HotelTime เขียน CSV รายปีจาก xlsx (`exporter/specs/05`, ตัดสิน 2026-09-08) เพราะ xlsx ของ
HotelTime มี `styles.xml` ผิดสเปกที่ `openpyxl` อ่านไม่ได้ และวันที่บางรายงานเป็น Excel serial · ตรวจใหม่แล้วพบว่า
ตัวแปลงของ uploader ซ่อม `styles.xml` เองแล้ว: แปลง xlsx ดิบของ HotelTime ได้ 46/46 ไฟล์ วันที่ serial ออกมาเป็น
ISO และนับแถวตรงกับที่ exporter นับ ส่วน CSV ของเรากลับ**ทำข้อมูลหาย** เพราะตัวอ่านของเราอ่านแค่ชีตแรก
(`occupancy-by-nationality-stay-reason` ตกชีตที่ 2 ทุกรอบ) และเขียนวันที่เป็นข้อความ วัน/เดือน ซึ่งกำกวมกว่า ISO

**ทางที่เลือก:** เลิกเขียน CSV เก็บและส่งเฉพาะ**ไฟล์ดิบ** ตามไบต์ที่ Site ให้มา · เปลี่ยนชื่อไฟล์เป็นชื่อแบบ ISO
ของเราได้ เพราะ HotelTime ใช้ชื่อไฟล์ซ้ำข้ามรายงาน (เช่น `document_folder.xlsx` ใช้กับ 3 รายงาน) แต่เนื้อไฟล์ห้ามแก้
และส่ง sha256 ไปด้วย · ด่านตรวจทุกด่านยังอยู่ อ่านไฟล์โดยไม่แก้ไฟล์ · exporter ส่ง**ทุกรายงาน** รวมรายงานที่มี
ข้อมูลส่วนตัวหนัก (`guest-profiles`, `foreign-police-profiles`, `city-tax`) เพราะเจ้าของระบบกำหนดให้ uploader มีสิทธิ์
สูงสุดในการจัดการข้อมูลเหล่านี้ exporter มีหน้าที่แค่ export และ upload

**ทางที่ไม่เลือก:** แก้ CSV ให้อ่านทุกชีตแล้วส่ง CSV ต่อ (ยังเป็นสำเนาที่ผ่านการแปลงของเรา ไม่ใช่ source of truth) ·
ตัดคอลัมน์ข้อมูลส่วนตัวก่อนส่ง (ขัดกับไฟล์ดิบ และเป็นการตัดสินแทนเจ้าของข้อมูล)

**ผลที่ตามมา:** วันที่ที่เป็นข้อความ วัน/เดือน ในไฟล์ดิบ (HotelTime 6 ไฟล์, FoodStory 11 ไฟล์) uploader ต้องอ่านให้ถูกเอง
เราแก้ให้ไม่ได้แล้ว · ช่วงวันของไฟล์ส่งผ่าน manifest ไม่ใช่ให้ uploader เดาจากชื่อไฟล์ (spec ของ uploader อ่านวันที่ใน
ชื่อไฟล์เป็นเวลาที่ export) · CSV ที่เคยเขียนไว้แล้วยังเก็บไว้ตาม ADR-0005
