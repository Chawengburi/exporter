# คู่มือผู้ใช้ exporter + Windmill

เอกสารนี้เขียนให้คนที่**ไม่ใช่คนพัฒนา**ก็เข้าใจได้ว่าระบบนี้ทำอะไร ไฟล์ไหนคือ "สคริปต์"
ใช้งานยังไง และถ้าอยากได้ข้อมูลใหม่จาก HotelTime ที่ยังไม่มีวันนี้ ต้องเริ่มจากตรงไหน — ถ้าอยาก
รู้เหตุผลเชิงลึกว่าทำไมถึงออกแบบแบบนี้ ให้ไปอ่าน `exporter/specs/` แทน (เขียนไว้ละเอียดกว่านี้
มาก แต่เข้าใจยากกว่า)

**ภาพรวม:** `exporter` คือโปรแกรมที่เข้าเว็บ HotelTime (ระบบจัดการโรงแรม) แทนคน ดึงข้อมูลการจอง
ออกมาเป็นไฟล์ **Windmill** คือตัวจัดตารางที่สั่งให้ `exporter` รันเองทุกวันโดยไม่ต้องมีคนพิมพ์
คำสั่ง

## ส่วนที่ 1 — ทำความเข้าใจ exporter

### ไฟล์ไหนคือ "สคริปต์" บ้าง

อยู่ใต้ `exporter/src/` ทั้งหมด — ไม่ต้องรู้จักทุกไฟล์ รู้แค่ 3 กลุ่มนี้พอ:

| กลุ่ม | อยู่ที่ | หน้าที่ |
|---|---|---|
| **คำสั่งหลัก** | `src/index.ts` | จุดเริ่มของโปรแกรม กำหนดว่าพิมพ์ `exporter` ตามด้วยอะไรได้บ้าง |
| **การกระทำ** | `src/commands/login.ts`, `export.ts`, `sweep.ts` | โค้ดจริงของแต่ละคำสั่ง (ล็อกอิน / ดึงข้อมูล / กวาดเมนู) |
| **นิยามรายงาน** | `src/reports/*.ts` | **ไฟล์ที่คุณน่าจะต้องแตะถ้าอยากเพิ่มรายงานใหม่** — หนึ่งไฟล์ = หนึ่งรายงานที่ดึงได้ |
| เครื่องมือกลาง | `src/core/*.ts` | ของที่ทุกรายงานใช้ร่วมกัน (ล็อกอิน, เขียนไฟล์, ตรวจสอบ ฯลฯ) — ปกติไม่ต้องแตะ |

ตอนนี้มี 3 รายงานที่ดึงได้แล้ว ดูได้ด้วยคำสั่ง:

```bash
cd exporter
node src/index.ts reports
```

```

  คอลัมน์ที่ใช้กรอง: Reserved:

reservations-ratecode
  Reservation search by RateCode  ·  /pms/reports/ResListRateCode.aspx
  ...

reservations-cancelled
  Search cancelled reservations  ·  /pms/ResDeleteList.aspx
  ...
```

### วิธีอ่านไฟล์นิยามรายงานหนึ่งใบ (ไม่ต้องรู้ TypeScript ลึก)

เปิด `exporter/src/sites/hoteltime/reports/reservations-search.ts` ดูตัวอย่าง — โครงสร้างของทุกไฟล์ในกลุ่มนี้
หน้าตาเหมือนกันหมด มีแค่นี้ที่ต้องรู้ว่าคืออะไร:

| ส่วนในไฟล์ | ความหมายเป็นภาษาคน |
|---|---|
| `id`, `label`, `path` | ชื่อรายงาน กับ URL ของหน้าเว็บที่ไปดึง |
| `allowedControls` | **รายการปุ่ม/ช่องกรอกที่อนุญาตให้แตะเท่านั้น** — กันเผื่อสคริปต์เผลอไปกดปุ่มอื่นที่แก้ไขข้อมูลจริงในโรงแรม (เช่นปุ่มคืนสถานะห้อง) ถ้าลองแตะอะไรที่ไม่อยู่ในนี้ โปรแกรมจะหยุดทำงานทันทีแทนที่จะแตะไปเงียบ ๆ |
| `chunk` | ดึงทีเดียวทั้งปีได้ไหม หรือต้องแบ่งเป็นรายเดือน (เพราะเว็บมีเพดานจำนวนแถวต่อครั้ง) |
| `dateColumn` | ใช้คอลัมน์ไหนตรวจว่าตัวกรองวันที่ทำงานจริง |
| `applyFilters(...)` | ฟังก์ชันที่กรอกช่องวันที่แล้วกดปุ่มค้นหา |
| `hasResults(...)` | เช็คว่าค้นแล้วเจอข้อมูลไหม (ก่อนจะกดปุ่ม export) |
| `expectedRowCount(...)` | อ่านจำนวนแถวที่หน้าเว็บบอกไว้ เพื่อเทียบกับไฟล์ที่ได้จริง (กันข้อมูลหายกลางทาง) |

**จุดที่สำคัญที่สุดสำหรับคนที่ไม่ใช่โปรแกรมเมอร์:** `allowedControls` คือเกราะป้องกันหลักของ
ทั้งระบบ — ถ้าจะให้ AI ช่วยเขียนรายงานใหม่ ให้ตรวจทานรายการนี้เป็นพิเศษว่ามีแค่ปุ่ม "ค้นหา"/
"export" เท่านั้น ไม่มีปุ่มที่ดูเหมือนจะไปแก้ไข/ลบ/ยกเลิกอะไร

### วิธีใช้สคริปต์ (รันตรงจาก terminal)

```bash
cd exporter

# ตรวจว่า credential ใน .env ยังล็อกอินได้
node src/index.ts login --check

# ดึงรายงานหนึ่งใบ ช่วงที่กำหนดเอง
node src/index.ts export --report reservations-search --from 01/01/2026 --to 31/01/2026

# ดึงทุกรายงานพร้อมกัน เฉพาะของใหม่ที่ขอบหน้า (รอบรายวัน) — ครบ 8 ใบ
node src/index.ts export --report all --daily --json

# ดึงทุกรายงานย้อนหลังทั้งหมด (back-fill / baseline) — ได้รายงานช่วงวันที่ 4 ใบ รายงานรายวัน
# 4 ใบ (arrivals, departures, in-house-guests, housekeeping) ถูกข้ามเพราะดึงได้เฉพาะ --daily
# (ADR-0003) — ขึ้นเป็น "ข้าม" ใน skipped ไม่นับว่าล้ม
node src/index.ts export --report all --baseline --json

# FoodStory ทั้ง 49 รายงานของเดือนที่แล้ว (reservation-report รันใบสุดท้าย) — ต้องมีคนแก้ reCAPTCHA ตอน login (รันบน Windmill ไม่ได้)
node src/index.ts export --site foodstory --report all --headful

# FoodStory รอบรายวัน = เมื่อวาน (เวลาไทย) วันเดียว → data/foodstory/daily/<เดือน>/<เมื่อวาน>/ — ไม่ไล่เก็บวันที่พลาด
# (รอบรายเดือนครอบคลุมให้) และข้ามการเช็คไขว้ยอดขาย (ADR-0006, ticket 10) — ต้องมีคนแก้ reCAPTCHA เหมือนกัน
node src/index.ts export --site foodstory --report all --daily --headful

# ดูให้เห็นว่ามันทำงานยังไง เปิดหน้าต่างเบราว์เซอร์จริง หน่วงให้ตามทัน
node src/index.ts export --report reservations-search --last-days 3 --headful --slow-mo 300
```

ผลลัพธ์เป็นไฟล์ CSV ที่ชื่อขึ้นต้นด้วยช่วงข้อมูล (เช่น `2026-10-05_2026-10-07__reservations-search.csv`) บวกไฟล์ดิบ `.xlsx` กับ
`manifest.json` ใต้ `_raw/<ชื่อรายงาน>/` และสรุปผลใน `_summary.txt` — รอบ `--daily` ลงคลังผลลัพธ์ที่ `exporter/data/hoteltime/daily/<เดือน>/<วัน>/`
หนึ่งโฟลเดอร์ต่อวัน (ชื่อไฟล์ขึ้นต้นด้วยช่วงข้อมูล ไฟล์ดิบอยู่ใน `_raw/` และมี `_summary.txt` สรุปผล) รอบย้อนหลัง
(`--from`/`--to`, `--last-days` ด้วย) ลงโฟลเดอร์ของตัวเองที่ `exporter/data/hoteltime/backfill/<YYYY-MM-DD_HHMMSS>/`
และรอบ `--baseline` ลง `exporter/data/hoteltime/baseline/<วันที่รัน>/` (ทุกใบเก็บไว้ ใบล่าสุดที่ผ่านเป็นใบอ้างอิง)
บรรทัดสุดท้ายของผลบอกว่าอยู่โฟลเดอร์ไหน

## ส่วนที่ 2 — ใช้งานผ่าน Windmill

ปกติไม่ต้องพิมพ์คำสั่งเองแล้ว เพราะ Windmill ตั้งให้รันวันละครั้งอัตโนมัติอยู่แล้ว (ดู
[`windmill/INSTALL.md`](../windmill/INSTALL.md) ถ้าต้องติดตั้งใหม่) ส่วนนี้อธิบายว่าถ้าอยาก
**ดูว่ามันทำงานสำเร็จไหม** หรือ **เพิ่ม/แก้สคริปต์เอง** ต้องทำยังไง

เปิด `http://localhost:8000` ล็อกอิน แล้วเลือก workspace **"Admins"**

### วิธีเพิ่มสคริปต์เข้า Windmill

1. เมนูซ้าย → **"+ New"** (หรือ `/scripts/add`) เลือกภาษา **Bash**
2. ตั้ง path เช่น `u/<ชื่อคุณ>/ชื่อสคริปต์`
3. เขียนเนื้อหาสคริปต์ — ถ้าสคริปต์ต้องเปิดเบราว์เซอร์จริง (เช่นเรียก `exporter`) **ต้องตั้ง
   tag เป็น `chromium`** ที่ช่อง "tag" มุมขวาบน ไม่งั้นจะไปรันบน worker เริ่มต้นที่ไม่มี
   Playwright/Chromium ติดตั้งแล้วพังทันที
4. กด **Test** ก่อนเพื่อดูว่ารันผ่านจริง แล้วค่อยกด **Deploy** เพื่อให้มี path ถาวรที่ schedule
   (ด้านล่าง) ชี้ไปหาได้ — กด Test อย่างเดียวไม่พอ ตั้ง schedule ไม่ได้จนกว่าจะ Deploy

ตัวอย่างจริงที่ใช้งานอยู่ (script `u/admin/pms_export_daily`):

```bash
#!/bin/bash
set -euo pipefail
cd /workspace/exporter
node src/index.ts export --report all --daily --json
```

ผลของแต่ละวันลงโฟลเดอร์ของวันนั้นใน `exporter/data/hoteltime/daily/` เอง ไม่มีขั้นก๊อปเก็บท้ายสคริปต์แล้ว
(เลิก 2026-10-07) · exit code `0` = ผ่านหมด, `2` = ผ่านบางใบ, `1` = ไม่ได้อะไรเลย — 2 กับ 1 ทำให้ job ขึ้น
"Failed" เพื่อให้มีคนเห็น — ดูรายละเอียดที่ `windmill/INSTALL.md` § 5

### วิธีดู log / ผลลัพธ์

- **ระหว่าง/หลังกด Test** — panel "Logs & Result" ด้านล่างจอแก้ไขสคริปต์ แสดง stdout ทั้งหมด
  ของโปรแกรม (สำหรับ exporter คือ JSON ที่มี `ok`, `reports`, `failed`, `totalRows`)
- **ย้อนหลัง** — เมนู **Runs** (`/runs`) กรองตาม path ของสคริปต์ได้ คลิกเข้าไปดูแต่ละรอบ จะเห็น
  สถานะชัดเจน: **"Successfully ran in ...s"** หรือ **"Failed after ...s"**
- **หน้า result JSON อ่านยังไง** — `ok: true` แปลว่าทุกรายงานสำเร็จ, `failed: []` ว่าง = ไม่มี
  ใบไหนล้ม, `totalRows` = จำนวนแถวรวมที่ดึงได้ ถ้า `ok: false` ให้ดูใน `failed[]` แต่ละรายการจะมี
  ข้อความ error บอกว่ารายงานไหนล้มเพราะอะไร (เช่น `LoginError` = ล็อกอินไม่ผ่าน)
- **ไฟล์ข้อมูลจริง** (CSV/xlsx) ไม่ได้อยู่ใน Windmill — มันเขียนลง `exporter/data/hoteltime/daily/<เดือน>/<วัน>/` บน
  เครื่องเหมือนรันมือ เพราะ Windmill แค่ "ยืม" เครื่องเดียวกันรัน `exporter` ให้

### วิธีตั้ง cron (schedule)

1. เมนู **Schedules** (`/schedules`) → **New schedule**
2. เลือกสคริปต์ที่ Deploy แล้วจาก dropdown
3. ตั้ง **Cron** — รูปแบบ 6 ช่อง `วินาที นาที ชั่วโมง วัน เดือน วันในสัปดาห์` เช่น
   `0 0 12 * * *` = เที่ยงวันทุกวัน ตั้ง **Timezone** เป็น `Asia/Bangkok`
4. กด **Save**

🔴 **กับดักที่เจอมาแล้วจริง:** ช่อง **"Permissioned as"** ผูกกับ user ที่ล็อกอินอยู่ตอนนั้น ถ้า
user คนนั้นถูกลบ/เปลี่ยนภายหลัง schedule จะ **แก้ไม่ได้และรันไม่สำเร็จเองด้วย** โดยหน้าจอไม่บอก
เหตุผลตรง ๆ (ขึ้นแค่ error ทั่วไป) — ถ้าเจอปัญหานี้ ให้เปิดแก้ schedule แล้วเปลี่ยน
"Permissioned as" เป็น user ปัจจุบันที่ล็อกอินอยู่ (จะมีคำว่า "(me)" กำกับให้เห็นชัด) แล้ว Save
ใหม่ — รายละเอียดเต็มอยู่ใน [`windmill/INSTALL.md`](../windmill/INSTALL.md) § 6

### วิธีเช็คว่ารอบอัตโนมัติทำงานจริงไหม (ไม่ใช่แค่ตอนกดมือ)

เข้า **Runs** แล้วดูคอลัมน์ **"Triggered by"** — ถ้าเป็นรอบที่ schedule ยิงเอง จะไม่ใช่ชื่อ user
คน (เช่นไม่ใช่ "admin") แต่จะเป็นชื่อระบบทำนอง `schedule-u-...` — นั่นคือหลักฐานว่าไม่มีใครกดมือ

## ส่วนที่ 3 — อยากได้ข้อมูลใหม่ที่ยังไม่มี (recon + เขียนรายงานเอง)

รายงาน 3 ใบตอนนี้เป็นแค่ส่วนเล็ก ๆ ของทั้งเว็บ HotelTime (204 หน้า มี 66 หน้าที่กดดึงข้อมูลได้
วัดไว้แล้วจริง) ถ้าอยากได้ข้อมูลจากหน้าอื่น ทำตามขั้นตอนนี้:

### ขั้น 1 — กวาดเมนูดูว่ามีหน้าไหนบ้าง (sweep)

```bash
cd exporter
node src/index.ts sweep
```

สคริปต์นี้ **อ่านอย่างเดียว ไม่คลิกไม่กรอกอะไรเลย** เดินทุกลิงก์ในเมนูแล้วบันทึกผลลง
`exporter/recon/menu-sweep.json` แบ่งเป็น 3 กลุ่ม:

- `hasExport` — หน้าที่มีปุ่ม export จริง (**เริ่มมองหาที่กลุ่มนี้ก่อน**)
- `noExport` — ตอนเปิดหน้ายังไม่เห็นปุ่ม export — **ไม่ได้แปลว่าดึงไม่ได้**: บางหน้าปุ่มโผล่หลังกด
  ค้นหา/แสดงผลเท่านั้น (ตัวกวาดไม่กดอะไร) และบางหน้าขึ้นกับพารามิเตอร์ใน URL (เช่น Cash book
  `curr=compl` ไม่เห็นปุ่ม แต่ `target=Cash` เฉย ๆ เห็น) ทุกรายการมี `buttonNames` และ `searchButton`
  (ปุ่มชื่อคล้าย Find/Show/Search/Display) — หน้าที่มี `searchButton` คือผู้สมัครที่ควรให้เจ้าของข้อมูล
  เห็นด้วย (`noExportWithSearchButton` บอกจำนวน, รอบ 2026-09-28 ได้ 38 จาก 139) ต้องยืนยันตอน recon
  เชิงลึกเสมอ
- `unreachable` — เปิดไม่ได้ตอนกวาด

แต่ละรายการในกลุ่ม `hasExport` มีชื่อหน้า, ลิงก์ (`href`), และ `inputNames` (ชื่อ control ในฟอร์ม
ของหน้านั้น — เอาไว้ใช้ตอนเขียน `allowedControls` ในขั้น 4)

### ขั้น 2 — เลือกหน้าที่อยากได้ แล้วตอบคำถาม 10 ข้อนี้ให้ครบ

รายการนี้กลั่นมาจากกับดักจริงที่โปรเจกต์นี้เคยเจอมาแล้วทั้งหมด (อยู่ใน
`.scratch/pms-export-cheap-recon-and-daily-runs/spec.md` § Further Notes ด้วย):

1. คีย์ของแถวคืออะไร (ใช้ตรวจว่าซ้ำหรือขาด)
2. **มีช่องวันที่ที่เป็นอดีตล้วน แก้ย้อนหลังไม่ได้ไหม** — ข้อนี้สำคัญที่สุด ถ้าไม่มี หน้านี้ทำ
   "รอบรายวัน" อัตโนมัติไม่ได้เลย
3. แถวเก่าถูกแก้ย้อนหลังได้ไหม นานแค่ไหน
4. เพดานแถวเท่าไหร่ (ดึงทีเดียวได้กี่แถวก่อนโดนตัด)
5. ในหน้าผลลัพธ์มีปุ่มที่เขียนข้อมูลไหม (ปุ่มที่ไม่ใช่แค่ดู/ดึงข้อมูล)
6. มีฟิลด์บังคับที่ห้ามล้างไหม
7. timezone ของค่าที่แสดงตรงกับตัวกรองไหม
8. มีปุ่ม export ไหม หรือต้องอ่านจากตาราง HTML แทน
9. ผลว่างแล้วหน้าทำตัวยังไง (ไม่ส่งไฟล์เลย หรือส่งไฟล์เปล่า)
10. มีข้อมูลส่วนบุคคลไหม

ตอบได้ด้วยการเปิดหน้านั้นดูจริง (ให้ AI agent เปิดผ่าน browser tool ก็ได้) ลองกรอกแล้วกด
ค้นหาดูว่าเกิดอะไรขึ้น — ยังไม่ต้องกด export จริงจนกว่าจะมั่นใจ

### ขั้น 3 — recon เชิงลึก

ขั้นนี้แพงกว่า sweep เยอะ (ต้องอ่านโครงหน้าให้ละเอียด) จึงทำเฉพาะหน้าที่เลือกจากขั้น 1-2 แล้ว
เท่านั้น — หาว่าช่องกรอกวันที่ชื่อ control อะไร (บางส่วน sweep ให้มาแล้วใน `inputNames`),
ปุ่มค้นหาชื่ออะไร, ปุ่ม export ชื่ออะไร, หัวตารางของผลลัพธ์มีอะไรบ้าง

### ขั้น 4 — เขียนไฟล์นิยามรายงานใหม่

สร้างไฟล์ใหม่ที่ `exporter/src/sites/hoteltime/reports/<ชื่อรายงาน>.ts` เลียนแบบโครงสร้างของ
`reservations-search.ts` (ดูตารางในส่วนที่ 1) — สิ่งที่ต้องระวังที่สุด:

- **`allowedControls` ต้องมีแค่ control ที่ `applyFilters` แตะจริง** ไม่ใส่เผื่อ ไม่ใส่ปุ่มที่ดู
  น่าสงสัยว่าจะแก้ไขข้อมูล
- ใส่ `dateColumn`/`dateColumns` ให้ตรงกับที่สำรวจได้จริงในขั้น 2-3 ไม่ใช่เดา

แล้วไปเพิ่มชื่อเข้า `exporter/src/sites/hoteltime/reports/index.ts` (มีคอมเมนต์บอกไว้แล้วว่า "เพิ่มรายงานใหม่
โดยเพิ่มไฟล์แล้วมาต่อท้ายที่นี่")

### ขั้น 5 — ทดสอบก่อนปล่อยจริง

```bash
node src/index.ts export --report <ชื่อรายงานใหม่> --last-days 3 --headful --slow-mo 300
```

เปิดเบราว์เซอร์ให้เห็นว่ากรอกถูกช่อง กดถูกปุ่ม แล้วเทียบจำนวนแถวที่ได้กับที่หน้าเว็บบอกไว้เอง
ก่อนจะเอาไปตั้งใน Windmill (ทำตามขั้นตอน "วิธีเพิ่มสคริปต์เข้า Windmill" ในส่วนที่ 2)
