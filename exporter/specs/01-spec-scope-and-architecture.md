# 01 · ขอบเขตและสถาปัตยกรรม

## ปัญหา

ข้อมูลจาก HotelTime PMS ย้ายเข้าคลังเอกสารด้วยมือคนทุกวัน: เปิดเว็บ → ล็อกอิน → ตั้ง filter →
กด export → ได้ไฟล์ → อัปโหลด · ต้นทุนที่มองไม่เห็นคือ **วันที่ไม่มีคนก็ไม่มีข้อมูล และไม่มีใครรู้**
กับ **ไม่มีใครตรวจว่าไฟล์ที่ได้ถูกช่วงวันที่จริงไหม**

ต้นทางไม่มี API ที่เราจะใช้ (เป็นการตัดสินใจของเจ้าของ ไม่ใช่ข้อจำกัด) โจทย์นี้จึงเป็นงาน
ควบคุมเบราว์เซอร์ตั้งแต่ต้น

## รูปแบบที่เลือก — AI เขียน สคริปต์รัน

AI เข้ามาได้สามจังหวะ เราใช้จังหวะที่ 1 กับ 3 **ข้ามจังหวะที่ 2**

| จังหวะ | ใคร | ความถี่ | ในโปรเจกต์นี้ |
|---|---|---|---|
| สำรวจเส้นทางครั้งแรก | AI ขับ มีคนดู | ครั้งเดียวต่อรายงาน | ✅ ผลอยู่ใน `recon/NOTES.md` |
| ขับตอนรันทุกรอบ | โมเดล | ทุกคลิก | ❌ **ข้าม** — จ่าย token ทุกคืนเพื่อความไม่แน่นอน |
| ซ่อมเมื่อพัง | AI ขับ | ~สิบครั้ง/ปี | ⬜ ยังไม่ทำ (นอกขอบเขตรอบนี้) |

**เหตุผลที่ข้ามจังหวะที่ 2:** เส้นทางรู้ล่วงหน้าครบแล้ว ไม่มีขั้นไหนต้องใช้วิจารณญาณ ·
สคริปต์พัง = เห็นทันที ส่วน agent ที่หลงทางจะ "หาทางอื่นจนสำเร็จ" แล้วส่งไฟล์ที่ดูสมเหตุสมผล
แต่ผิดเข้าคลังเงียบ ๆ ซึ่งเป็นความเสี่ยงอันดับ 1 ของทั้งงาน

ที่มาเต็มของสถาปัตยกรรมนี้อยู่ใน artifact สองใบ:
[Portal to Pipeline](https://claude.ai/code/artifact/776ec534-b87d-4500-8bb3-30f0c8485d97) ·
[Agent เขียน สคริปต์รัน](https://claude.ai/code/artifact/79616963-d0f3-4bb3-86cd-a4f4e07b53f9)

## ขอบเขตรอบนี้

**ทำ** — ล็อกอินอัตโนมัติ · ดึง 3 รายงานในหมวด Reservations ตามช่วง created date ·
ชั้นตรวจว่าไฟล์ที่ได้คือไฟล์ที่สั่ง · รวมผลเป็น CSV รายปี · เก็บไฟล์ดิบพร้อม provenance

**จงใจไม่ทำ** — และไม่ควรมีใครเผลอเติมเข้ามาโดยไม่คุยก่อน:

| ไม่ทำ | เหตุผล |
|---|---|
| ขาอัปโหลดเข้า uploader | เจ้าของกำหนดขอบเขตรอบนี้ให้แคบไว้ที่ขา export เท่านั้น |
| cron / รัน 24 ชม. บน Ubuntu | ยังไม่ถึงขั้นนั้น · ต้องมีตัวเลขอัตราการพังจากการรันจริงก่อน |
| ชั้น AI ซ่อมเมื่อพัง | ต้องรู้ก่อนว่าพังบ่อยแค่ไหนและพังด้วยเหตุอะไร |
| ระบบต้นทางอื่น (hotelline, line chat) | คนละเส้นทาง คนละกับดัก |

## เลือกใช้ Playwright บนเครื่องเราเอง ไม่เช่าเบราว์เซอร์

เพราะ **ไม่มี anti-bot และไม่มี 2FA** (วัดจริง ดู spec 02) ตัวเลือกแพง ๆ อย่าง Skyvern
($149/เดือน ขายจุดแข็งเรื่อง 2FA/CAPTCHA) จึงไม่มีเหตุผลให้จ่าย

ถ้าวันหนึ่งเจอ anti-bot ทางหนีไฟคือเช่าเบราว์เซอร์ที่ patch มาแล้ว (เช่น TinyFish Browser API
~$0.002/นาที) ซึ่ง **เปลี่ยนแค่บรรทัดเชื่อมต่อใน `core/session.ts`** ไม่ต้องเขียนสคริปต์ใหม่ —
นี่คือเหตุผลที่สินทรัพย์ของเราต้องเป็นสคริปต์ Playwright ไม่ใช่ prompt ของ agent เจ้าใดเจ้าหนึ่ง

## ไม่มี build step

Node 22.18+ รัน `.ts` ตรง ๆ ด้วย native type stripping · `tsc` เหลือหน้าที่ typecheck อย่างเดียว
(`npm run typecheck`) ลดชิ้นส่วนที่ต้องดูแลไปหนึ่งชั้น

ผลที่ตามมาที่ต้องรู้: **import ภายในโปรเจกต์ต้องลงท้าย `.ts` เสมอ** และ **ห้ามใช้
`enum` / `namespace` / parameter property** ซึ่ง type stripping ไม่รองรับ (บังคับด้วย
`erasableSyntaxOnly` ใน `tsconfig.json`)
