# 05 · ผลลัพธ์และหลักฐานที่มา

## สองรูปแบบ — เลือกด้วย `--format`

ไฟล์ `.xlsx` ดิบ **ถูกดาวน์โหลดทุกรอบอยู่แล้ว** เพราะชั้นตรวจต้องอ่านมัน · `--format` จึงคุมแค่ว่า
จะ **เก็บอะไรไว้** หลังตรวจเสร็จ การเลือก `raw` ไม่ได้ทำให้ช้าลงเลย

| ค่า | ผล |
|---|---|
| `raw` | เก็บ `.xlsx` ดิบ + `manifest.json` ไม่เขียน CSV |
| `csv` | เขียน CSV รายปี แล้ว **ลบ** ไฟล์ดิบทิ้ง |
| `both` | เก็บทั้งคู่ — **ค่าเริ่มต้น** |

| | ไฟล์ดิบ `.xlsx` | CSV รายปี |
|---|---|---|
| ที่อยู่ | `downloads/raw/<report>/` | `downloads/<report>-<ปี>.csv` |
| ผ่านการแปลงของเรา | **ไม่เลย** — ไบต์ตรงจาก HotelTime | อ่าน → รวมก้อน → แปลงวันที่ → เขียนใหม่ |
| จำนวนไฟล์ | หนึ่งต่อหนึ่งก้อน | หนึ่งต่อหนึ่งปี |
| Excel serial | ยังดิบ (`45658`) | แปลงเป็น `01/01/2025` |
| ไลบรารีทั่วไปอ่านได้ | ❌ `openpyxl` อ่านไม่ได้ | ✅ ได้หมด |
| เหมาะกับ | **หลักฐาน / ตรวจย้อนหลัง** | ใช้งานจริง · DuckDB · parquet |

**ถ้าจะเก็บเป็น source of truth ให้ใช้ `raw` หรือ `both`** · แต่ต้องรู้ว่าไฟล์ดิบเป็นไฟล์ที่
ไลบรารีมาตรฐานอ่านไม่ได้ ต้องใช้ตัวอ่านใน `core/xlsx.ts`

## ตัดสินใจ: ผลลัพธ์เป็น CSV ไม่ใช่ xlsx

1. ไม่ต้องพึ่งไลบรารีเขียน xlsx และไม่ต้องผลิต `styles.xml` ที่ผิดสเปกซ้ำ
2. ปลายทางคือ uploader ที่แปลงทุกอย่างเป็น markdown อยู่แล้ว และงาน parquet/DuckDB
   (spec 13 ของ uploader) อ่าน CSV ได้ตรง ๆ
3. แก้เรื่อง Excel serial ได้ในตัว เพราะเราเขียนวันที่ออกมาเป็นข้อความเองทั้งหมด

รูปแบบ: RFC 4180 · CRLF · **มี UTF-8 BOM** เพื่อให้ Excel เปิดชื่อผู้เข้าพักภาษาไทยได้ไม่เป็น
ตัวยึกยือ (DuckDB กับ markitdown ข้าม BOM ให้เอง)

## การรวมเป็นไฟล์รายปี

จัดกลุ่มตามปีของ **วันที่ในแต่ละแถวเอง** (คอลัมน์ `dateColumn`) ไม่ใช่ปีที่ก้อนเริ่ม

จำเป็นเพราะรายงานที่ดึงทั้งช่วงทีเดียว (RateCode) มีก้อนเดียวที่เริ่มปี 2024 แต่ข้างในมีข้อมูล
ถึง 2026 — ถ้าจัดกลุ่มจากช่วงของก้อนจะได้ไฟล์ชื่อ `-2024.csv` ที่บรรจุข้อมูลสามปี
**ชื่อไฟล์โกหกเนื้อใน** (เป็นบั๊กจริงที่แก้ไปแล้ว)

ทุกคอลัมน์ใน `dateColumns` ถูกแปลงเป็น `DD/MM/YYYY` เหมือนกันหมดก่อนเขียน

## `manifest.json` — ทำให้ไฟล์ดิบใช้เป็นหลักฐานได้จริง

เขียนไว้ข้าง ๆ ไฟล์ดิบทุกครั้งที่ `--format` เป็น `raw` หรือ `both`

บันทึก: report id · **URL ต้นทาง** · คอลัมน์ที่ใช้กรอง · ช่วงที่สั่ง · `fetchedAt` ·
กลยุทธ์การแบ่งก้อนพร้อมเหตุผล · `totalRows` · และต่อไฟล์: ชื่อไฟล์ · ช่วงที่สั่ง ·
**ช่วงจริงในไฟล์** · จำนวนแถว · ชื่อที่ HotelTime เสนอมา · ขนาด · **sha256**

รวมทั้ง `emptyRanges` — ช่วงที่ค้นแล้วไม่มีข้อมูล ซึ่งเป็นข้อมูลสำคัญพอกัน เพราะบอกได้ว่า
"ไม่มีข้อมูล" ต่างจาก "ยังไม่ได้ดึง"

`sha256` คิดจากไบต์ทันทีที่ดาวน์โหลดเสร็จ **ก่อนแตะอะไรทั้งสิ้น** จึงยืนยันได้ว่าไฟล์ที่เก็บไว้
คือไฟล์เดียวกับที่ HotelTime ส่งมา

## โฟลเดอร์ raw ถูกล้างก่อนทุกรอบ

`downloads/raw/<report>/` ถูกลบทิ้งแล้วสร้างใหม่ทุกครั้งที่รัน · ไม่งั้นไฟล์ค้างจากรอบที่ล้ม
กลางทางจะปนกับรอบใหม่ แล้ว `manifest.json` จะไม่ตรงกับไฟล์ที่อยู่จริงในโฟลเดอร์

ลำดับที่ตั้งใจ: **ตรวจผ่าน → เขียน manifest → ค่อยลบ (ถ้า `--format csv`)**

## ข้อมูลส่วนบุคคล

ทั้งไฟล์ดิบและ CSV มี **ชื่อผู้เข้าพัก** · `downloads/` ทั้งโฟลเดอร์ถูก gitignore
และต้องไม่ commit · ถ้าจะทำหน้าสรุปหรือส่งต่อ ให้ใช้เฉพาะ metadata จาก `manifest.json`
(จำนวนแถว ช่วงวันที่ checksum) ไม่ใช่ตัวข้อมูล
