# 06 · credential และ session

## ที่เก็บ credential

`pms-export/.env` (gitignored) + `.env.example` (committed เป็นต้นแบบ)

ลำดับความสำคัญ ล้อ `bobby-cli/src/core/config.ts`:

```
shell env  >  pms-export/.env  >  ค่า default ใน src/core/config.ts
```

`dotenv` จะ *ไม่* ทับตัวแปรที่ตั้งมาจาก shell อยู่แล้วเป็นค่า default ซึ่งให้ลำดับนี้พอดี

## แยก credential ออกจาก Config ที่ระดับ type

`loadConfig()` คืนเฉพาะค่าที่ไม่เป็นความลับ · credential อยู่ใน `loadCredentials()` ที่เป็น
ฟังก์ชันคนละตัว

**เหตุผล:** ทำให้ `console.log(config)` ทำรหัสหลุดไม่ได้ตั้งแต่แรก แทนที่จะพึ่งวินัยว่า
"ระวังอย่าพิมพ์" · คอมไพเลอร์บังคับให้ต้องตั้งใจเรียก `loadCredentials()` ถึงจะแตะรหัสได้

## การกรองความลับ

ทุกข้อความที่จะพิมพ์ออกจอหรือลงไฟล์ผ่าน `core/redact.ts` ก่อนเสมอ

**ทำไมต้องมี:** ข้อความ error ของ Playwright ชอบแนบ HTML ของหน้าหรือค่าที่กรอกลงฟอร์มมาด้วย
และ WebForms echo ค่าที่ post กลับมาใน `__VIEWSTATE` — รหัสผ่านหลุดลง log ได้ง่ายกว่าที่คิด

ความลับที่สั้นกว่า 4 ตัวอักษรไม่กรอง เพราะจะทำลายข้อความจนอ่านไม่ออกและ mask เองก็ไม่ช่วยอะไร ·
กรองทั้งรูปแบบตรงและ url-encoded

## ทำไมล็อกอินใหม่ทุกรอบ ไม่ใช้ persistent profile

cookie ที่ได้หลังล็อกอินมีสามใบ:

| cookie | อายุ |
|---|---|
| `provider_htdb_thai_07_forms` (ตั๋ว Forms Auth) | **session** |
| `provider_htdb_thai_07_sessid` | **session** |
| `provider_htdb_thai_07_forms.usrsHistData` | 1 ปี |

ใบที่ให้สิทธิ์จริงสองใบเป็น session cookie ทั้งคู่ — หายเมื่อปิดเบราว์เซอร์ และฝั่ง server
(ASP.NET) ยังหมดอายุเองได้อีกชั้น · การเก็บโปรไฟล์ไว้จึงให้ **ความรู้สึกปลอม** ว่า
"ล็อกอินค้างไว้แล้ว" แล้วไปพังตอนกด export

ทำได้เพราะ **ไม่มี 2FA** · ล็อกอินใช้เวลา ~5 วินาทีต่อรอบ ซึ่งถูกกว่าความเสี่ยง

### กับดักเพิ่มเติมของ persistent profile

`usrsHistData` อยู่ได้ 1 ปี ถ้าเก็บ cookie ข้ามรอบ repeater บนหน้า login จะสะสมผู้ใช้จน
**มีหลายแถว** แล้ว `uniqueByRole('textbox', 'Login')` จะล้มเพราะเจอหลายชิ้น ·
การเปิด context ใหม่ทุกรอบทำให้เรื่องนี้ไม่เกิดเลย

## ด่านกัน session หลุดกลางทาง

`assertStillLoggedIn()` ถูกเรียก **ก่อน** กด export ทุกครั้ง

ถ้า session หมดอายุกลางทาง WebForms จะเด้งกลับหน้า login แล้วการกด export ต่อจะได้
ไฟล์ที่ "ดูปกติแต่ว่างเปล่า" ซึ่งไหลเข้าคลังได้โดยไม่มีใครรู้ — ต้องล้มดัง ๆ ตรงนี้เท่านั้น

## ยังไม่ได้วัด

**อายุจริงของ session** — ประมาณ ~20 นาทีจากค่า default ของ ASP.NET แต่ยังไม่ได้ทดสอบ ·
การรันย้อนหลังนานสุดที่ทำจริงคือ 92 วินาที จึงยังไม่เจอปัญหา · ถ้าวันหนึ่งรายงานเยอะขึ้น
จนเกิน ต้องออกแบบให้ re-login ระหว่างชุด

**lockout จากการล็อกอินซ้ำ ๆ** — ยังไม่รู้ว่า HotelTime ล็อกบัญชีหลังพยายามผิดกี่ครั้ง
รอบสำรวจยิงผิดไป 1 ครั้งแล้วไม่มีอะไรเกิดขึ้น
